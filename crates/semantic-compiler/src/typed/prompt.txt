Aggregate queries use group(field,alias), aggregate(function=count|sum|min|max,field,distinct,alias), metric(name,alias), and order_output(slot,direction,nulls). Grouping also projects its dimension. Count with field:null counts rows (distinct must be false); count(field) ignores null values; count with distinct:true counts distinct nonnull values. Sum/min/max ignore nulls and return null on empty input; count returns zero. Group-only queries return distinct groups, including the null group. Explicit aggregate operations express an explicit user calculation; a named governed metric must use metric(name,alias) and its exact catalog definition. Metric filters apply only to their metric. Catalog row policies always apply before grouping. A metric's compatible_dimensions is an explicit grouping whitelist; never invent additive behavior over time. Aggregate ordering uses order_output with the requirement ID of the target group/aggregate/metric, not its alias. Row ordering cannot appear in an aggregate query. Sum supports signed Int16/Int32/Int64 and Decimal128; min/max support these plus Utf8, Date32 and Timestamp. Multi-fact composition requires further capabilities; do not approximate it with different operations.

An explicit ratio calculation uses ratio(numerator,denominator,zero=null|zero,alias), where each component is {"function":"sum|count|min|max","field":{"instance":"r","field":"amount"},"distinct":false}. Average of integer rows is sum(field)/count(field), not count(*) when nulls occur. Named ratio_metrics use metric(name,alias), preserving both authored component metrics, their individual filters, compatible dimensions, declared shared source grain, zero behavior and unit. Never replace a named ratio metric with a convenient row-level division or inferred filter.

Relative whole-calendar filters use calendar_filter(field,period={"unit":"day|iso_week|month|year","offset":-1,"count":1}).
